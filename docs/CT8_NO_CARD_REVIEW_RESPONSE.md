## Corrections made

| Review finding | Correction and local evidence |
| --- | --- |
| Cold start makes the Worker assertion stale; upstream timeout escapes | Worker fetches `/health/ready` before stamping or signing, allows a bounded cold wake (75 s, then 10 s retry), then signs for the current boot. Upstream exceptions return a generic 504. A Worker test advances the clock by 25 seconds during readiness and checks that the assertion uses the later time and that an upstream timeout returns 504. Real Render cold-start behavior still requires staging verification. |
| Captured assertion can replay after API restart | Python generates a new random boot token for each app instance, returns it with `Cache-Control: no-store` on readiness, and requires it in the signed assertion before reading the request body. An old assertion is rejected after restart even inside the 15-second skew. A Python test checks success, same-process replay denial and post-restart denial. Only one API process and one instance are permitted. |
| Previous signing key cannot be selected | Worker uses `PILOT_ASSERTION_KEY_ID`; Python requires `CT8_NOCARD_ASSERTION_KEY_ID` and, if rotating, distinct `CT8_NOCARD_ASSERTION_PREVIOUS_ID` paired with its old key. A Python test accepts the old key under its explicit ID, rejects reused proof, and accepts the current key. |
| Weak repeated signing keys pass | All three Worker signing/session/login keys and the Python current/previous assertion keys must be canonical base64url strings decoding to at least 32 bytes, with a minimum of 16 distinct bytes including in the first 32. Tests reject 64 repeated `a` characters. These structural checks cannot prove a key was randomly generated; generate real provider secrets using Python `secrets.token_urlsafe(48)` and never place them in a ZIP. |

Confirm exactly one Render instance in the live environment. |

| Callback preserves the login-state cookie on denials | Every callback failure, including rate denial, clears the browser login cookie. Local Worker tests cover malformed callback and failed GitHub exchange. Stateless signed state can still be replayed if a browser deliberately resends a saved cookie with another valid single-use GitHub code; provider-side distributed one-time state remains an explicit review question. |
| IP-only rate limit; synchronous validation | Authenticated API admission is keyed by numeric user ID; login and callback remain IP-keyed. ## Exact no-card launch recipe, **for later review only**

- Build: `pip install -r requirements.txt`
- Start: `python -m uvicorn cat_treaty.pilot_nocard_api:create_nocard_app --factory --host 0.0.0.0 --port $PORT --workers 1`
- Python must receive `CT8_NOCARD_ENABLED=true`, `CT8_PILOT_ENABLED=false`, `CT8_MEASURE_ENABLED=false`, `WEB_CONCURRENCY=1`, `CT8_NOCARD_API_HOST`, `CT8_NOCARD_PUBLIC_HOST`, `CT8_NOCARD_ASSERTION_KEY_ID`, `CT8_NOCARD_ASSERTION_KEY`, `CT8_NOCARD_ID_ALLOWLIST`, `CT8_NOCARD_LIMITS_JSON`, `CT8_NOCARD_DEADLINE_SECONDS` and `CT8_NOCARD_RESULT_BYTES`. Optional rotation requires **both** `CT8_NOCARD_ASSERTION_PREVIOUS_ID` and `CT8_NOCARD_ASSERTION_PREVIOUS`. No numeric envelope is approved by this recipe.
- Worker additionally requires `PILOT_ASSERTION_KEY_ID` matching the Python active or previous identifier; its assertion key must match that identifier. Use the actual Worker hostname for `PILOT_PUBLIC_HOST` and the actual Render hostname for `PILOT_ORIGIN_HOST`. Separate provider-held secrets are required for the session, login and GitHub OAuth client. `VITE_CT8_PILOT_MODE=true VITE_CT8_NOCARD_MODE=true` builds the separate UI; leave `VITE_CT6_API_BASE_URL` unset.
- Rotation sequence: add old key + old ID as Python previous while old Worker remains; install new key + new ID as Python current; switch Worker to new pair; remove previous pair only after old in-flight requests expire. Keep the Render service suspended during this local review.
