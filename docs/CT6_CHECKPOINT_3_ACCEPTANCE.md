# CT6 Checkpoint 3 Acceptance — Hours-Clause Orchestration

**Specification:** CT6 v1.0  
**Checkpoint:** Bounded hours-clause election and CT5 processing  
**Status:** Accepted

The hours orchestrator now:

1. validates and calculates the explicitly disclosed CT2 source record;
2. constructs the immutable CT3 program-terms source;
3. generates and classifies all CT4 candidate windows and candidate sets;
4. retains rule-specific exclusion codes, reasons and affected IDs;
5. elects only from valid sets using the authorized contractual method;
6. blocks invalid/manual/geometry failures before CT5 or completed identities;
7. passes only elected occurrence rows and their elected-window times to CT5;
8. applies annual capacity, reinstatement premium and settlement in order;
9. calculates CT4 tail/frequency and CT5 six-perspective analytics; and
10. builds CT4 and CT5 identities with CT4 identity reproduction.

Acceptance evidence includes:

- a valid multi-window election through CT5;
- exact preservation and calculation of the disclosed source loss/inuring record;
- rejection evidence for an invalid higher-recovery overlapping split;
- invalid manual election with no downstream ledger or identity;
- out-of-term exclusion evidence;
- deterministic repeated identities; and
- complete regression of catalogue and CT1–CT5 behavior.

The CT5 result contract now accepts either a completed catalogue result or a
selected hours-clause result with its matching CT4 simulation input. Existing
catalogue behavior and constructors remain backward compatible.
